# 语言设计

人物一开口，露馅最快的就是台词。现在的模型让律师、街头少年和十四岁初中生说同一种客服腔：语法完整、用词中上、礼貌周到、谁说都行。这个 skill 给每个角色建一份**角色语言档案**，从语言习惯上约束和设计他说的话，再按档案写台词、查台词。

马克·吐温在《哈克贝利·费恩历险记》卷首写过一段说明：书里用了好几种方言（密苏里黑人方言、西南边远林区方言、派克县方言和它的四种变体），这些深浅差别是凭着对这几种说话方式的熟悉、下了功夫一点点做出来的，不是随手做的，也不是靠猜。这个 skill 要做的就是这件事，只是把「熟悉」拆成了可以逐项写、逐项查的维度。

**只管说出来的话**：用词、句子、语用。不管音色、语速、TTS 参数（配音用 `minimax-tts`），不管长相和造型（用 `juese-sheji`）。

## 两条底层原则

开工前读 `references/principles.md`。

1. **用词有阶级性。** 一个人的用词水平体现他的身份和阶级，用词的精准度（articulate 的程度）体现他的教育、知识量、阶级和身份。所以说话方式要由一组**语言坐标**一起推：国别地区、出身阶级、现在的阶级、教育、职业、年龄代际、社群、母语。不能只挑一个口音标签。
2. **自下而上。** 档案是提示和约束，不是定死的规则。每条写**倾向**（通常怎么说）、**边界**（绝不会怎么说）、**例句**和**来源**（〔样本〕〔台词〕〔推测〕〔待定〕〔待核〕）。第一版只写有把握的几条，写出台词之后再从「这句像他、那句不像」里归纳，补进档案，每次升版本号并写明来自哪句。人在特定处境下会说出不像自己的话，记进「例外登记」。

还有几条反刻板的底线（不拼错字模拟口音、写语法不堆俚语、方言角色不负责好笑、标准语也是口音），在 `principles.md` 第三节，每次都要守。

## 先选模式

| 用户想要 | 模式 | 读 |
|---|---|---|
| 「这是某人的访谈 / 口播稿 / 聊天记录，照着他的说话方式建档」「学这个人说话」 | **S 从样本建档** | `references/principles.md`、维度文件（按需）、`templates/角色语言档案.md`，跑 `scripts/yuyan_tool.py stats` |
| 「这个角色怎么说话」「给他建语言档案」，手上是人设、小传或 juese-sheji 的人物精细描述，或者只有一个身份标签 | **P 从人设建档** | `references/principles.md`、`references/维度索引.md`，再按坐标打开维度文件；`templates/角色语言档案.md` |
| 「写这场戏的对白」「把这段台词改成他的说法」「同一句话让四个人各说一遍」 | **W 写台词 / 改台词** | 角色的语言档案；`references/03-语体与切换.md`、`references/07-惯用词与口头禅.md` |
| 「这段台词像不像他」「哪几句出戏」「检查一下对白」「对白太 AI 了」 | **C 检查与回写** | 角色的语言档案、`references/check-labels.md`、`templates/检查报告.md`；英文台词跑 `scripts/yuyan_tool.py variety` |

最常见的顺序是 **P（或 S）→ W → C → 回写档案 → W**：档案先出一版，写一场戏，查一遍，把写对了的新习惯补进档案，下一场按新档案写。用户只要其中一个时，做完那一个就停，结尾用一句话说下一步可以做什么。

## 共同的第一步：收料

先读手上有的东西：剧本、人物小传、分镜稿、juese-sheji 的人物精细描述（尤其第 ④ 段「说话方式参考」）、已有的语言档案、已经写好的台词、用户给的样本。

然后确认这几件事，用户没说的**一次性问完**（有 AskUserQuestion 这类工具就用，没有就一次列清楚）：

1. **台词用什么语言**：英文、中文，还是双语（中文剧本配英文字幕、英文剧配中文字幕）。
2. **时代和地点**：决定变体、俚语年份、该不该有某些词。
3. **给谁看**：出海短剧给美国观众时，英国角色的「外来感」是卖点；给英国观众时，英式细节要更准。
4. **拼写跟谁走**：剧本按美式统一，还是英国角色用英式拼写（`references/01-国别地域与口音.md`）。

说「你定」就从剧本推，并在档案里标〔推测〕。

**产出存在哪**：和 juese-sheji 同一个约定，一部短片一个目录 `shorts/<项目>/`，语言档案放 `character-sheets/<角色>/语言档案.md`，和角色卡放在一起。用户的工作区有自己的结构就按他的来；只是试一试、没有项目时，直接在对话里给。

## 模式 P　从人设建档

1. **列语言坐标。** 按 `principles.md` 第一节的坐标表，把人设里能读出来的填上，每一项写依据（小传第几段）。**出身阶级和现在的阶级分开写**：两者不同的人有两套语码，最有戏。人设里没有、又影响说话的项（他在哪读的书？读什么科？青春期在哪几年？）问用户，或者补一个并标〔补〕。
2. **按坐标打开维度文件。** 先看 `references/维度索引.md` 的「坐标 → 维度」表，判断要细做哪几个维度：英国人必看 `01a-英式角色.md`；AAVE、律师、方言看 `02`；高学历的欧美角色看 `05-外语夹用.md`；用词水平 `04` 每个角色都看。
3. **逐维度写倾向、边界、例句、来源。** 用 `templates/角色语言档案.md`。只有身份标签时，推出来的全部标〔推测〕；没把握的维度写〔待定〕，不硬填。**宁可一个维度空着，也不要写一条泛泛的「说话粗鲁」**：形容词是请模型猜，具体的词和句式才是下单。
4. **定切换表**：对上级、家人、陌生人、下属、同社群的人、喜欢的人，各用哪一档，变化点是什么（`03-语体与切换.md`）。
5. **口头禅、称呼、骂人的词都写频率上限**（`07-惯用词与口头禅.md`）。
6. **反刻板自查**：按 `principles.md` 第三节过一遍。AAVE 和方言角色重点查：是不是只有俚语没有语法、有没有拼错字、他有没有和口音无关的目的。
7. **试音**：同一个意思（比如「我不同意」或「我饿了」）在三种处境下各说一句：对上级、对家人、生气时。试音句放进档案末尾，作为 v1 的样板。
8. **标 v1**，写日期和依据。

## 模式 S　从样本建档

样本是一个真人的文字或口播转写（比如主库 `稿件/` 里的口播稿、某人的访谈）。

1. **分样本**：口语转写还是书面？对谁说的？什么场合？口语和书面分开算，不同场合分开记。**能用来建档的是口语样本**；书面样本只能用来推用词档位。
2. **跑统计**：`python3 scripts/yuyan_tool.py stats 样本.txt`（剧本格式加 `--speaker 名字`）。拿到平均句长、碎片句比例、填充词密度、缩写率、长词和拉丁后缀词比例、高频词。数字只是线索，规则要回到原句里去确认。
3. **逐维度归纳**：每条规则附 1–2 句样本原句，标〔样本〕。分清「这个人的习惯」和「这个场合的习惯」：只在一个场合出现的，写进切换表，不写成总倾向。
4. **样本不够时**：英文三百词、中文六百字以下，或者只有一个场合，归纳出来的规则标〔推测〕，档案开头写清样本量。
5. 后面同模式 P 的第 4–8 步。

## 模式 W　写台词 / 改台词

1. **读档案和场景**：谁对谁说、他想要什么、阻力在哪、这个处境属不属于「例外登记」。
2. **先定意图和潜台词**，再落词。落词的顺序：语体档（对这个人用哪一档）→ 用词档 → 句长和句式 → 语用（怎么请求、拒绝、道歉）→ 惯用词（守上限）→ 情绪方向。
3. **多个角色同场**：写完后遮住名字读一遍，每句都要能认出是谁说的。认不出的那句，回档案找一个维度把它拉开（盲测思维，见 `evals/cases.md`）。
4. **改台词**：给「原句 → 改后 → 改了哪个维度」三列，改动理由用 `check-labels.md` 的标签。
5. **英文台词**：按档案的变体过一遍词表和拼写；英国角色跑 `python3 scripts/yuyan_tool.py variety 台词.md --target uk --speaker 名字`，美国角色用 `--target us`，澳洲角色用 `--target au`（不要用 uk，会把澳洲词全报成穿帮）。
6. **交付**：剧本格式的台词。用户要时，附一列旁注：这句用了档案的哪几条。写的过程中如果出现了档案里没有、但写得特别对的说法，在交付末尾列出来，问要不要回写（见模式 C 第 4 步）。

## 模式 C　检查与回写

1. **逐句打标签**：按 `references/check-labels.md`，每句一个或几个标签（`OK`、`GENERIC`、`TOO_FORMAL`、`TOO_ARTICULATE`、`WRONG_VARIETY`、`TIC_OVERUSE`、`EYE_DIALECT`、`STEREOTYPE`、`EXCEPTION_OK`、`NEW_HABIT`……），附依据（档案的哪一条）。
2. **机器能查的先让机器查**：英文台词跑 `variety` 查变体穿帮，跑 `stats --speaker` 看句长和口头禅有没有超上限。
3. **给改法**：出戏的句子给 1–2 个改写，说明改了哪个维度。
4. **回写档案（自下而上）**：标了 `NEW_HABIT` 的句子，归纳成新规则补进档案，来源标〔台词〕并写明场次和原句；标了 `EXCEPTION_OK` 的新处境，登记进「例外登记」；被台词证实的〔推测〕升级成〔台词〕，被推翻的删掉。档案升一个版本号，在版本记录里写改了什么、来自哪句、为什么。
5. 用 `templates/检查报告.md` 交付：一张逐句表 + 改法 + 档案改动摘要。

## 和其他 skill 的分工

都是可选的，没有也能用。

- **上游 `juese-sheji`（角色设计）**：它的第 ④ 段「说话方式参考」只有语速、口头禅和三句示例。要细做角色说话时，拿它的人物精细描述走模式 P；它写的语速、音色不进语言档案（那是配音的事），口头禅和句式可以当〔推测〕的初值。
- **下游 `minimax-tts`（配音）**：语言档案不管音色和语速。台词里有外语短语（法语、拉丁语）或方言词时，交付时提醒一句配音要注意发音。
- **`cinematic-director`（导演）**：它的对白和声音方案管「这场戏说什么、怎么拍」；这个 skill 管「这个人会怎么说」。

## 交付时要列的

- 哪些规则来自参考资料（`references/sources.md`），哪些是这次按人设推的（〔推测〕）。
- 拿不准的语言学说法、方言词、外语短语、俚语年份，放进档案的「待核」栏，不要当事实写。
- 用了真人或影视角色做参考（Klaus、Lucifer 等）时，说明借的是哪几条机制；不复用原台词。
